> 토큰에서 가져오도록 바꿔, 이후 고객사 추가 시 E2E 파일도 고칠 필요가 없게 했습니다.

### 코드 수정 없이 자동으로 반영된 것

- 상단 **고객사 선택** 목록, `?brand=saebom-oriental` 링크
- 색·모서리(12px)·제목 세리프체·밀도가 **모든 화면과 공통 컴포넌트**에 적용
- **다크 모드** 팔레트
- **Storybook** 툴바의 고객사 전환
- 테마 대비 테스트(`describe.each(brandIds)`)와 E2E 접근성 검사 대상

### 명도 대비 자동 보정

브랜드 가이드의 연두색은 흰 글자와의 대비가 기준(4.5:1)에 못 미쳐, 테마 팩토리가 브랜드 색 계열을 유지한 채 보정했습니다.

| 모드   | 가이드 색 | 적용 색   | 글자색    | 대비                       |
| ------ | --------- | --------- | --------- | -------------------------- |
| 라이트 | `#7FA33A` | `#5F792B` | `#FFFFFF` | 2.92 → **4.93** : 1        |
| 다크   | `#7FA33A` | `#7FA33A` | `#1A1A1A` | **5.97** : 1 (보정 불필요) |

라이트 모드 적용 색은 버튼 위 흰 글자뿐 아니라 흰 카드·페이지 배경 위 글자(텍스트 버튼, 링크)로 쓰일 때도
4.5:1 이상이 되도록 모든 표면을 기준으로 보정됩니다.

## 고객사 추가 절차

1. `packages/theme/src/tokens.ts` 의 `brandIds` 에 ID 추가
2. `packages/theme/src/brands.ts` 에 `BrandTokens` 객체 작성 후 `brands` 에 등록
   - 색은 브랜드 가이드 값을 그대로 넣는다 (대비는 자동 보정)
   - hex 색상은 이 패키지에서만 허용 (ESLint 로 강제)
3. `npm test` — 새 고객사의 라이트/다크 대비 테스트가 자동으로 실행된다
4. `npm run e2e` — 모든 페이지 접근성 검사에 자동 포함

타입 안전성: `brands` 는 `Record<BrandId, BrandTokens>` 이므로 1번만 하고 2번을 빠뜨리면(또는 반대) 컴파일 오류가 납니다.
